# ADR-0028: Terminology is data: stable keys, labels from layers, and no label ever decides authority

Status: Accepted by the owner (portability slice S4, 2026-10-17). Production approval remains external governance.
Closes findings P-05, P-06 and P-07 (fixed business vocabulary in dashboards, register sets, pages, help and examples), the label part of R-05 and R-06, and stage B of P-09 (the guard) in `docs/PORTABILITY_AUDIT.md`. P-04 (pack feature flags) stays open for S6; P-02b (the role catalogue) for S5/S8. Builds on ADR-0024 (pack resolved by organisation) and ADR-0026 (external packs).

## Context

Generic pages, messages, notifications, dashboards, exports and role names spoke procurement ("Supplier", "Category Owner", "Legal Review", "Group Head of Procurement") whatever the organisation did. The Blank pack could not read as a neutral product, and a second business could not call its records by its own names without a code change. The words are data; the keys behind them are code.

## Decisions

| # | Decision |
|---|---|
| D1 | **Stable key versus label.** A terminology key (`supplier`, `legal.review`, `contract.owner`, …) is a machine identifier owned by the platform. A label is what a person reads. A label never decides authority, routing, state, storage or an audit action. |
| D2 | **Nothing stable is renamed in S4.** Role codes (`ProcurementAdministrator`, `CategoryOwner`, `Legal`, `Approver`, `BackupApprover`, …), permission codes, workflow state codes, configuration-kind keys, audit action codes, URL paths, form fields, database objects and pack identifiers keep their spelling. Administrator pages show the stable key next to the label. The brief's `GroupHeadApprover` does not exist as an identifier (the names are `Approver` and `GroupHeadProcurement`); both are kept. |
| D3 | **Resolution order.** (1) the organisation's published terminology, (2) the terminology of the organisation's assigned solution pack, (3) neutral platform terminology compiled into `TermCatalogue`, (4) the stable key as a last-resort diagnostic. Locale chain: exact locale, then language. An inactive entry removes an inherited override. |
| D4 | **Catalogue.** 42 keys in `Ecp.SharedKernel`; 32 are required in a complete document. Neutral wording names no business: Contract Administrator, Contract Owner, Reviewer, Registration Approver, Backup Approver, Contract Type, Contract Portfolio, Contract Register, External Execution, Review, Approval, Organisation, Business Unit, Site, Counterparty. Blank = neutral; JBS procurement wording lives only in the JBS pack. |
| D5 | **Configuration kind `Terminology`.** Versioned through the existing draft, validate, preview, publish, history, rollback and audit lifecycle, with the existing step-up and second-person rules. Overrides only (inherit the rest). Plain text only: markup, script, template and expression syntax are refused; length limits, duplicate prevention and a mandatory singular and plural. Tenant and organisation isolated. |
| D6 | **Pack terminology.** An optional pack document terminology/terminology.json (in the pack's own tree) (content type `Terminology`) in the pack format; covered by the manifest hash, content hash, signature and content scan; complete (all 32 required keys per base locale) when present. Installing or assigning a pack creates an organisation draft only and never overwrites a published release or an open draft. Packs without it (Blank 1.1.0, JBS 2.1.0) stay valid. Pack versions: Blank 1.2.0, JBS 2.2.0. |
| D7 | **One resolver.** `ITerminologyResolver` is the only reader. It returns a `TermSet` resolved once per page, supports many keys in one call, and fails safe to neutral wording. Generic pages never read pack files. Cache key = tenant, organisation, locale, published version (release id plus pack key and version); invalidated on publish and rollback; the cache failing falls back to persistence. Diagnostics log failures without label values. |
| D8 | **Home organisation.** Page-level wording is that of the person's home organisation (first active organisation-level assignment, else the tenant's first organisation, else the installation default pack). A page about one organisation's record describes it in that organisation's words. |
| D9 | **Constrained tokens.** `[[key|modifier…]]` (plural, short, lower, sentence, a, cap) in page text, domain messages, notification templates and stored migration text. No expressions or nesting. Tokens expand before `{0}` arguments, so user data can never be read as a token. Notification templates with an unknown key or modifier fail validation at save. Domain exceptions keep raw tokenised text for the Host and expose neutral text through `Message`. |
| D10 | **Permissions.** `terminology.read`, `.draft`, `.publish`, `.rollback`, `.audit.read`, least privilege (Tenant Administrator, Organisation Administrator, Business Configuration Administrator; Auditor reads); recorded as decision D7b. Publish and rollback follow re-authentication and second-person rules. |
| D11 | **History is not rewritten.** Audit entries, audit action codes, contracts, documents, workflow state, saved views, migration profiles, release hashes and pack identities are unchanged. Stored text written before S4 is plain and is left as written. |
| D12 | **Guard stage B.** An architecture test scans every text file shipped with the platform (Razor, resources, JSON, project and props files, appsettings, deployment files, workflows, scripts, CSS, JavaScript) case-insensitively for business and vendor names, fixed business labels, fixed Australian defaults and capitalised business words in page text. Allowed only through a written allow-list of single files with reasons (stale entries fail the build); packs, samples and documentation are not scanned. |
| D13 | **Left for later slices.** Regional defaults (S10: `en-AU`, Brisbane time zone, `AUD` in settings, the formatter fallback, the readiness probe), role-catalogue replacement (S5/S8), feature flags (S6), another pack-loader slice. Not in S4: live e-signature, reporting, operations, API work, AI, marketplace, visual designers. |

## Consequences

* P-05, P-06, P-07 and P-09 stage B are closed for all generic UI, messages, notifications and exports. A third business adopts its own words with a signed pack and no recompilation (proved in tests with a pack the repository has never seen).
* The stable key is the contract between code and data; labels can change at any time without a migration.
* Because stored text can carry tokens (migration messages, plan summaries), any new page that shows such text must expand it. The guard cannot see that; code review and the representative-page tests do.
* The cache is per process. Several instances converge through the release id in the key plus the ten-minute expiry.
* A custom label is plain text only. Rich text, per-record labels and translations beyond locale fall-back are not supported (*future*).
